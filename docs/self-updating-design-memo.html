Decision · approved · 24 September 2026

Keep Art Prep
up to date.

Use Sparkle, as Zag does, to check for releases automatically and let users choose when to install. Preserve unsaved outlines and active exports. Continue producing notarized ZIPs through the private Mac builder, with one release command.

This design is approved; implementation has not started. The first updater-enabled release requires a manual download; v1.0.2 cannot acquire an updater by itself.
ApproachTradeoff
Sparkle + release asset feed (recommended) Use existing public releases and private builder. Publish appcast.xml together with the ZIP.
Sparkle + GitHub Pages, as in ZagIndependent feed hosting, but adds Pages setup, a publishing branch, and a separate deployment to maintain.
Custom GitHub release checkerA download link is simple, but replacing and relaunching the app safely would duplicate Sparkle’s installation and verification machinery.

Experience

Check automatically. Install deliberately.

Add Check for Updates… and an Automatically Check for Updates toggle to the app menu. Automatic checks start enabled, matching Zag; unattended installation starts disabled. Sparkle owns scheduling, preference persistence, download progress, and errors.

Only an Art Prep bundle with a valid Kindly Ops Developer ID signature starts the updater. Development builds explain that updates are unavailable. CLI rendering and automated tests do not initialize Sparkle or contact the feed. Photos and project files remain local; GitHub receives ordinary update requests, not artwork. Do not enable Sparkle system-profile reporting.

An installation must not interrupt photo loading, refinement, or export. Defer the install while the workspace is locked and resume only through a documented Sparkle delegate path. Keep the existing unsaved-outline confirmation on termination: Cancel leaves the app and project intact. Do not copy Zag’s quit-prompt bypass, which serves its background gateway.

Users running from a read-only location or an uninstalled download must receive an actionable message through the manual check. Keep the existing bundle identifier local.artprep.mac and app name to preserve identity across releases.

Release flow

One signed release, one update feed.

Embed a checksum-pinned Sparkle framework and tools. Zag currently vendors 2.9.1 because SwiftPM’s artifact downloader hung on this Mac. Use the same verified-download approach with the current stable 2.10.0, confirmed against the upstream release API.

Configure the feed as https://github.com/kindlyops/artprep/releases/latest/download/appcast.xml. Keep the current monotonically increasing semantic version in both bundle version fields.

  1. Validate merged source and credentials on the existing trusted release path.
  2. Probe a dedicated Art Prep Ed25519 Keychain account with a bounded signing operation. Verify it matches the public key embedded in the app. Never export the private key into CI.
  3. Build and embed Sparkle, preserving framework symlinks and loader paths. Sign nested helpers and framework code inside out, then sign the app with Hardened Runtime and timestamp.
  4. Run app checks, notarize, staple, and verify the ZIP after extraction.
  5. Run Sparkle’s generate_appcast on the final archive. Require archive verification before extraction and signed feeds. Include macOS 14 and arm64 requirements; validate the generated XML, signature, version, byte length, and fixed repository download URL.
  6. Create a draft release with the ZIP, checksum, and appcast. Verify uploaded assets before publishing it as latest. Confirm that the public feed and archive resolve afterward.
The feed advertises the latest full ZIP only. Delta updates are not needed for this initial implementation. Failed uploads leave a draft and preserve the previous latest release.

Keep ./scripts/release.sh auto as the normal command. Add an explicit recovery path for finishing publication of an existing draft after verifying its source and assets; do not silently rebuild or overwrite a published version. Never change signed XML after signing it.

Keep runner selection, main-ancestry validation, and the GitHub App dispatch boundary in artprep-build. No new PR/fork triggers or public self-hosted jobs are needed.

Validation

Prove the update, including its refusal paths.

CaseRequired result
Unsigned app, CLI, unit testsNo updater network activity.
Manual check, no update, offlineCorrect Sparkle UI; editing remains usable.
Busy workspace; unsaved outlines; cancelNo lost work or interrupted export; normal quit protection remains effective after a failed update.
Missing key, wrong key, locked KeychainBounded preflight failure before notarization.
Altered archive or feedSignature verification rejects the update.
Malformed metadata, wrong version/URL/lengthNo public release is promoted.
Partial upload or publication failurePrevious feed remains available; retry uses verified draft assets.
Real signed older → newer appDownload, install, relaunch, correct version, and working GIMP export. Use isolated signed test builds and a local test feed first.

Extend Swift behavior tests and the existing Python release-boundary tests; use mutation checks on publication and signature gates. Run Swift formatting, shellcheck, shfmt, Ruff, ty, and relevant prek hooks. A mock release test alone does not prove Sparkle can install the app.

Before public rollout, confirm a stable Keychain tool path and backup the new signing key through an explicit secure user operation. ZIP updates with verification before extraction make loss of the Ed25519 key consequential; follow Sparkle’s supported rotation procedure.

Evidence & limits

Grounded in Zag’s implementation.

Reviewed Zag at f696e0e40af988a780b7796a7fe96459cc4934e4 and Art Prep at d752947df008891165ab28152e6c726b845762e1.

  • Zag updater: standard controller, automatic-check preference, signed-build gate, install lifecycle.
  • Zag release script: Keychain preflight, notarization, appcast generation. Its workflow publishes to zag-releases and serves the feed through Pages.
  • Sparkle 2.10.0: SwiftPM archive SHA-256 17e28312b8e18ab7cdbbe09a6fb28cc55a5479ec6c371dbc07cdecd2a14fd959.
  • Sparkle setup and publishing guide: embedding, signature verification, Keychain keys, feed generation, versioning, and real-update tests.

Art Prep’s Pages lookup returned 404, so no existing Pages feed was confirmed. Dedicated Art Prep key setup, binary embedding, GitHub release-asset feed redirects, and the actual Sparkle install/defer behavior remain implementation checks. No credentials were changed.

Adjacent documentation drift: README still describes direct self-hosted source builds; verification.md still predates successful notarization. Correct these release-related statements alongside the updater documentation.
